# 根系标注工具

模型先预测，人只改错的地方 —— 把 5472×3648 的甘蔗根系图变成能训练的 labelme 标注。

一份完整的、可以整个文件夹拷给别人的工具：`pictures/`（图）+ `model/`（权重）+
这个目录里的脚本 + `runtime/`（自带运行环境）。

---

## 快速开始

```
双击 run.bat          启动（没有黑窗口）
双击 run_debug.bat    启动并保留控制台（看进度和报错，出问题时用这个）
```

第一次拿到这个文件夹、且没有 `runtime/` 时，先双击 **`setup_runtime.bat`**
（联网一次，约 400MB）。装完之后就完全离线了，整个文件夹可以随便拷。

> 对方需要什么：**Windows x64**（Win10 1803 以上，因为脚本用了系统自带的 `curl.exe`/`tar.exe`）。
> 不需要装 Python、不需要显卡、不需要联网。

命令行（自己有 Python 环境时也能直接跑）：

```
python annotate_root.py                 # 打开第一张没做的
python annotate_root.py --image <名>     # 直接开某张
python annotate_root.py --prefetch      # 只跑预测填缓存，不开界面（32 张约 26s）
python annotate_root.py --selftest      # 无界面自检（24 项，会自己清理产物）
python annotate_root.py --no-gpu        # 强制 CPU 预测
```

## 工作流：两个阶段

### 阶段 1 · 修掩码（按 `1` 或 `Enter` 进入）

- **红色** = 模型预测的根（半透明）
- **蓝色** = 你涂的"这条预测错了，删掉"
- **绿色** = 你涂的"这里漏了，补上"
- 存盘时保留的是 **`(红 ∪ 绿) \ 蓝`** —— 也就是"模型说的 + 你补的 − 你删的"

预测常常整体偏粗或偏细，用 `[` `]` 调**预测松紧**比一根根拿蓝笔抠快得多：
调完立刻重算红层（几十~两百毫秒，用的是缓存的概率图，**不重跑模型**），已涂的绿蓝不受影响。

| 键 | 阈值 | 效果 |
| --- | --- | --- |
| `[` | −0.02（**更低**） | 红层**更粗** —— 低阈值把弱响应也拉进来，断续处更容易连上 |
| `]` | +0.02（更高） | 红层**更细** —— 越接近 0.50 就越只剩「确定是根」的像素 |

实测同一张图（面积只是个相对参考，绝对值随图变）：阈值 0.02 → 54228 px、0.10（默认）
→ 44249 px、0.30 → 34282 px、0.50 → 27022 px。**0.50 = 滞回关掉，只剩 0.5 以上的强响应**，
是最细的一档。范围卡在 0.02~0.60：**不能调到 0** —— 0 在底层是"关掉滞回"的特例，
会让掩码从最粗直接跳到最细。

**笔刷圈一直看得见** —— 涂的过程中也在（圈有一圈深色描边，涂到自己刚涂过的地方也不会"陷进去"
看不见）。只有平移时（中键拖动 / 空格+左键）才藏起来，那会儿手按着但并不是在涂。

### 阶段 2 · 画折线（按 `2` 或 `Enter` 进入）

折线用来记**根系长度**，同时**保存时每条折线各生成一个多边形**（见下）。每张图 8~10 根，
纯手画是最大的时间开销，所以：

- 按 **`G`** 让工具**照着刚修好的掩码自动起草**（骨架 → 分链，实测 0.14s）。
  掩码是折线的天然来源，两者天然自洽，不会出现"线画在掩码外面"。
  **`G` 会整条替换现有折线**，所以已经手工调过时会先问一句（防误触）；没调过就直接起草，
  连按两下不会弹两次。
- 起草完再**拖控制点**微调：`Alt+点击` 在离点击最近的位置插一个点、`Delete` 删掉选中的点、
  `X` 删掉整条。
- 起草这一步也进撤销栈，误按 `G` 一个 `Ctrl+Z` 就回去了。

**多边形预览**：画布上**紫色的轮廓**就是"存出来会是什么形状"，随改随变（150ms 防抖）。
`P` 可以关掉它。

### 保存时怎么生成 root 多边形（每条折线一个）

```
你修好的掩码（红∪绿\蓝） + 你画的折线 + 带宽 W
        ↓
① 先把掩码按"离哪条折线最近"分成 N 份（N = 折线条数）
② 每份抽成一条多边形 —— 宽度用的是**掩码自己的真实宽度**
③ 折线**逐点**检查：这一点没落在自己那份掩码里（哪怕是几像素宽的窄缝），
   就用宽 W 的带补上 —— 保证多边形是一条**沿折线的连续走廊**，
   折线一定完整落在自己的多边形里
        ↓
N 个 root polygon（与折线条数严格相等）

> ⚠️ ③ 用**逐点**判据是有教训的（2026-10-07 用户报"有些折线未被多边形包含"）：
> 原来的判据是"±宽度/2 内有掩码就算有"，而切片之间常有几像素宽的**窄缝**
> （1/4 尺度分区图放大后的块状边界），大窗口把窄缝全判成"有"→ 不补带 →
> 切片连不起来 → 最后"只留最大连通块"就把真实的一块根丢了。
> 实测某图一条 1290px 的折线只被包住 **51%**，整张图的多边形面积少 **13%**。
> 现在有一条合成用例（40px 宽的根 + 中间一道 4px 窄缝）专门钉这个。
```

- **带宽 W 在工具栏上可调**（数字框，或 `,` `.`），调完立刻重算 —— 它只作用在**掩码缺了**
  的地方；掩码有根的地方，轮廓还是掩码的真实宽度，不会被带宽撑粗。
  **它是工具级设置**：调一次，之后每张图都按它来（不是每张图各记一份），
  并写进 `settings.json`，**下次启动还记得**。想回默认值就把那个文件删掉（默认 10px）。
- **掩码里没有折线经过的块会被丢掉**（不然多边形数就对不上折线数）。丢了几块、多少面积，
  状态栏和保存时的提示里都会写。
- 缓存里的掩码是**唯一事实来源**：反复保存不会"多边形的多边形"越存越糙，也不会累积。

## 产物

```
datasets\
  <名>.json                        labelme 格式，labelme 本体能直接打开
      root  polygon                每条折线一个，轮廓取自掩码 —— 这是**分割真值**
                                   （掩码缺的段用带宽补，见上面「保存时怎么生成」）
      root  linestrip              你画的折线 —— 这是**根长真值**
      stem  polygon                预测的茎（按 D 丢弃就不写）
      check_background rectangle   预测的检查框（按 K 丢弃就不写）
  <名>.jpg                        原图（保存时从 pictures\ **移过来**：硬链接，不占额外空间）
  masks\<名>.png                  **像素级 root 掩码**：单通道黑底白条 —— 训练直接吃这份
  overlay\<名>_overlay.jpg         原图 + 最终掩码(红) + 折线(黄) + 茎(橙) + 检查框(绿)

settings.json                     界面偏好（现在只有一个：折线带宽）。删掉就回默认
cache\<模型名>\                   中间状态，删了只是重新预测（不丢标注）
  <名>_masks.png                  R=预测 G=绿笔 B=蓝笔（一张图装三层，能直接肉眼看）
  <名>_prob.npy                   模型概率图（2.7MB），「预测松紧」靠它才能秒级重算
  <名>_meta.json                  检查框 / 阈值 / 折线 / 丢弃标志
```

### 掩码（`masks\`）是训练真正用的那份真值

`masks\<名>.png` 是**你在阶段 1 一笔一笔改出来的那份 root 掩码本身**：单通道 8 位、
**黑底白条**（0=背景、255=根）、原始分辨率不缩放（约 200KB/张）。
root_model 训练时**优先读它来定 root 通道**（`common/dataset.py:load_root_mask_png`），
读不到才回退去栅格化 json 里的多边形。

**只存 root**：root 是人一笔笔改出来的、值得逐像素保真；**茎和检查框本来就是模型预测的、
人没动过**，训练时继续走 json 那条路，一个字节都没变。

比多边形准在哪（实测这批图合计）：

| | 多边形口径 | 像素掩码 |
| --- | --- | --- |
| 根面积 | 187394 px | 190429 px（**+1.6%**） |

差的是两件事：① 多边形化本身的轮廓近似（几百 px/张）；② **没画折线的根** ——
多边形口径下它们会被当成背景（等于往训练集里塞假负样本），掩码不会有这个问题。

> ⚠️ **两者是两把尺子，同一批数据要么都有掩码、要么都没有。** 老图（掩码功能之前存的）
> 只有多边形，补一遍就行：
> ```
> python annotate_root.py --backfill-masks
> ```
> 数据都在 `cache\` 里，**不用重新标**。
>
> 划分数据集时 `separate_dataset` 会把 `masks\` 一起搬过去（在子目录里，按"组"是分不到的），
> 所以划分完口径不会退回去。

**为什么 overlay 和 masks 都要放子目录**：`separate_dataset` 划分数据集时是**按文件名主干分组**的，
`datasets\<名>_overlay.jpg` 会被当成一个**独立的"只有图没有标注"的组**参与划分，
既多算一组还可能落错侧。放进子目录后 `iterdir()` 不递归，扫描器自然看不见它。

**做完的图会从 `pictures\` 移走**（保存时删掉 `pictures\` 里那份；数据不会丢 ——
`datasets\` 里那份是同一个 inode 的硬链接，跨盘时是独立副本，两种都先校验大小再删）。
于是 **`pictures\` 里还剩几张 = 还有几张没做**，在资源管理器里一眼就能数，不用开工具。
工具**两个目录都扫**，所以已经做完的图照样在左边列表里，点回去还能改。
不想要这个行为就加 `--keep-pictures`（原图留在 `pictures\` 不动）。

「这张做没做过」的判定 = `datasets\<名>.json` 存在。左侧列表标题常显「已完成 x / n · 还剩 y」。
重开工具会自动跳到第一张没做的；
已经做过的也能从左边列表点回去改，改完再存会覆盖（缓存里留着上次的编辑状态，能接着改）。

**不会写 root_model\datasets\** —— 那是训练数据，半自动标注的结果混进去会污染划分和对照工具。

## 设计决策（以及为什么）

- **最终掩码 = `(红 ∪ 绿) \ 蓝`**，显示优先级也是 蓝 > 绿 > 红。显示和存盘必须是同一个口径，
  否则会出现"屏幕上看着是红的，存出来那块没了"。
- **笔刷是"最后一笔赢"**：涂绿会清掉笔下的蓝，涂蓝会清掉笔下的绿，橡皮擦把绿蓝都清掉
  （回到纯预测，**不动红层** —— 红层是模型的东西，要改它只能用阈值）。不这么做的话同一像素
  既在绿里又在蓝里，用户会困惑。
- **掩码全程原图分辨率**（uint8 0/255），撤销用**差分补丁**（`np.packbits`）而不是全图快照：
  一张全图快照 20MB，50 步就是 1GB。
- **只有一块窗口大小的帧缓冲**，按 256×256 的**固定瓦片网格**重画：部分重画与整帧重画必须
  逐像素相同（否则涂笔刷时会出现颜色略有差异的方块），按固定网格切就能保证这一点。
  涂一笔只重画盖到的那 1~2 个瓦片（0.5ms），平移/缩放才整帧重算（48ms）。
- **掩码降采样用面积平均**（`INTER_AREA`），缩小时细根不会像最近邻那样整片消失；
  放大用最近邻，边界是"诚实的像素"。
- **预测口径一行都没抄**：全部走 `_vendor\` 里那份 root_model 的冻结快照
  （`common.predict.predict`），检查范围限定、滞回阈值、跨尺度上采样只在那边写了一次。
- **缓存按模型名分目录**：掩码是"某个模型在某张图上的输出"，换模型后混用旧缓存会静默给出
  错误掩码 —— 那比多等几分钟糟得多。
- **不开 HighDpi**：开了 dpr 变 1.5，帧缓冲尺寸/鼠标坐标/ROI 换算三处都要乘 dpr，
  是"鼠标点和笔迹错位"的经典 bug 源。

### 已知取舍（不是 bug）

- **掩码导出成多边形会少 4% 的面积**（实测 16 张 GT：掩码 1316963 px，多边形只盖住
  1264771 px；最差的一张少 7.4%）。原来写的是"1~2%、轮廓近似"，**那个说法不对** ——
  2026-10-08 查清了，主因不是轮廓近似，而是**掩码切片里"不在折线正上方"的那些块被
  「只留最大连通块」丢掉了**：实测被丢的最大一块有 7458 px，而它离折线只有 **12 px**
  （折线是画了的，是多边形没盖住它）。
  **对训练与评测没有任何影响** —— 两者吃的都是 `masks\<名>.png`（逐像素掩码），
  多边形只在 labelme 里看、或者显式用 `--no-gt-mask` 时才起作用。
- **多边形不再覆盖整张掩码**：每条折线只拿「它那一份」掩码，折线到不了的根尖/侧枝、
  以及没有折线经过的块，都会落在多边形之外。**想让某块进标注，就给它画一条折线。**
- **导出参数是 `approx_px=1.0, min_area=100`，不是函数默认值**。默认的 `min_area=400`
  在真预测掩码上会丢掉 10 个连通块里的 3 个、4.75% 的像素 —— 一根 40px 长的细根面积才
  400px²，正好卡在阈值上被整根丢掉。
- **折线目前还没有下游消费者**：`root_model` 训练时用的是多边形（`build_target_masks`
  只看多边形），折线是"把根长真值记下来"用的，等根长口径落地时才会有人读它。
- **CPU 版 torch，每张图预测约 3 秒**（GPU 版 0.8 秒）。这是为了"拷给谁都能跑"付出的代价，
  32 张图全量重跑也就一分半钟。

## 发给别人

整个文件夹拷过去即可（实测约 1.5GB：图 124MB + 权重 119MB + 预测缓存 105MB + runtime 1.2GB）。

- 对方**不需要**装 Python / 显卡 / 联网；
- 对方的 `datasets\` 是空的，从第一张开始标；
- 想再加新图片：丢进 `pictures\`，工具会认（新图没有缓存，会自动跑预测，CPU 每张约 3 秒）。

`_vendor\` 是 root_model 的**冻结快照**（`config.py` + `common\`），保证这个文件夹自包含。
**root_model 那边改了预测口径的话这里要重新同步**，否则这个工具标出来的掩码和训练时算的
真值不是一套口径：

```
xcopy /E /Y "..\..\root_model\config.py" "_vendor\"
xcopy /E /Y /I "..\..\root_model\common" "_vendor\common\"
```

（同步后要重新跑一次 `--prefetch`，旧缓存是按旧口径算的。`cache\` 里的目录名带模型名、
不带代码版本，所以换口径后**要手动删掉 `cache\<模型名>\`**。）

| 点了列表里的图，提示"这张图不在了" | 文件被删/被挪走了。按 `F5` 重新扫描，它就从列表里消失 |
| 在资源管理器里删了几张图，工具列表里还在 | 按 `F5` |
| 双击 run.bat 一闪而过 | 双击 `run_debug.bat`，控制台里会留下报错 |
| `runtime\ not found` | 先跑 `setup_runtime.bat`（要联网一次） |
| 预测很慢 | 正常，CPU 每张 3 秒。想快就跑 `--prefetch` 一次性全跑完 |
| 报"检查范围预测异常/没有前景" | 模型在这张图上没认出托盘，退回全图统计。这张图建议按 `K` 丢弃 check 标注 |
| 红层整体偏粗/偏细 | 用 `[` `]` 调松紧，别硬涂 |
| 想从头再来 | 删掉 `cache\` 和 `datasets\`，重新 `--prefetch` |

`python annotate_root.py --selftest` 会跑 8 段共 85 项检查（真模型预测 / 阈值重算与默认口径
逐位一致 / 笔刷与撤销重做 / 折线起草与插点 / 导出后回读校验 / 真开一个 offscreen 窗口
+ 合成鼠标事件走完整交互（含折线增删改、带宽旋钮、多边形预览）+ 从缓存续做），
产物一律写到临时目录，**不会碰你的 `datasets\`**。
